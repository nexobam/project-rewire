# 開発の教訓・再発防止＆ベストプラクティス記録（Lessons Learned）

このドキュメントは、本プロジェクト（Project Rewire）の開発・運用の中で発生した**ミス・不具合の原因と再発防止策**、および**効果が高かった設計方針・進め方（成功パターン）**をまとめたものです。
**今後コードの修正・新機能追加を行う際は、必ず作業前に本ドキュメントを確認し、同じミスを繰り返さないようにしてください。**

---

## 1. ミス・不具合と再発防止ルール（Must Check）

### 1-1. 指示の対象範囲を広げすぎて関係ない箇所まで変更したミス
* **発生事象**: 「絵柄の問題だけバスケの話をやめよう」という指示に対し、Lv.0〜4の全シードデータ・AI問題生成・Live英会話・表記までアプリ全体からバスケ（Miami Heat）を削除してしまった。
* **原因**: UIの出題形式（`exerciseType === 'picture_choice'` / `lv1Phase === 'picture'`）と、シードデータ全体のカテゴリ定義（`contentCategory: 'heat'`）を切り分けずに一括変更した。
* **再発防止**:
  * 修正前に「対象は特定の画面・フェーズ・出題形式だけか、アプリ全体か」をコードの分岐条件で正確に特定する。
  * 影響範囲を必要最小限（今回なら `SilentModePage.tsx` の絵カードフェーズ時のフィルタリングのみ）に留める。

### 1-2. 音声再生と画面遷移・選択肢のズレ（iOS Safari 含む）
* **発生事象**: サイレントモードで耳に聞こえる音声と、画面上の選択肢・正解表示が一致しないバグが再発した。
* **原因**:
  1. ホームで音声アンロック済みにもかかわらず、各モード画面のマウント時にも `unlockSpeechSynthesis()`（`speechSynthesis.cancel()` を伴う）を重複実行し、1問目の再生をキャンセルしていた。
  2. 「次の問題へ」のあと `useEffect`（非同期）で音声再生を開始していたため、iOS Safari でユーザージェスチャー外とみなされブロック／遅延していた。
* **再発防止**:
  * `unlockSpeechSynthesis()` は開始ボタンのタップ時のみ1回実行し、各ページマウント時には呼ばない。
  * 2問目以降の音声再生は、ボタンのクリックハンドラ内で**同期的に**開始する。
  * 選択肢配列に現在の正解（`currentChunk.id` / `enText`）が含まれていることを描画ガードで保証する。

### 1-3. 人間分析の数値と実装値の矛盾（4択の制限時間）
* **発生事象**: 「4択スキャン＋親指タップに最低2.4〜3.8秒かかる」と分析しておきながら、絵カード4択の緑上限を `3.2秒` に設定してしまい、普通に解いても黄色になりやすい厳しい判定になった。
* **再発防止**:
  * 認知・身体動作の分析を行った場合、緑の上限は「平均値」ではなく**「迷わず処理したときの最大値＋余裕」**に設定する。
  * 現行の確定基準：絵カード4択 `緑 <= 4.5s / 黄 <= 7.0s`、英文4択 `緑 <= 5.5s / 黄 <= 8.5s`。

### 1-4. モバイルUIのレイアウトシフト（5単語目タップ時のズレ）
* **発生事象**: 語順並び替え（`WordOrderBoard.tsx`）で、5単語目をタップして上部枠が2行目に折り返した瞬間に下の選択肢ボタンが下に押し下げられ、6単語目が押しづらくなった。
* **再発防止**:
  * ユーザーの操作中に中身が増えるコンテナ（`assembled-slots` 等）は `min-h` ではなく**固定高さ（`h-[168px] overflow-y-auto`）＋上詰め（`content-start`）**にし、下の操作エリアを1pxも動かさない。

### 1-5. デプロイ・実行環境コマンドのミス
* **発生事象**: `npm` のPATH不足や、`wrangler deploy` で `CLOUDFLARE_API_TOKEN` を付けずに実行して OAuth ログイン待ちでタイムアウトした。
* **再発防止**:
  * テスト・ビルド時は `scratch/node/bin` のPATHを含めて実行する。
  * `wrangler deploy` 実行時は必ず認証トークン環境変数と `--config wrangler.toml` を確認してから実行する。

### 1-6. 外部AI連携（Live会話JSON）の情報量不足と厳格すぎるZodバリデーション
* **発生事象**: Live実戦モードで外部AIに出力させるJSONの情報量が少なく（単語リストのみ）、さらに `overallReview` や `fluencyScore` が欠落・別名になった際に Zod の英語生エラー配列が表示されて取り込めなかった。
* **再発防止**:
  * 外部AIの手動貼り付けJSONは、キー名の揺れや一部項目の省略があっても自動補完して取り込める寛容なパーサーにする（エラー時も必ず日本語で案内する）。
  * 会話ログは単なる文字列リストではなく、「話したトピック・会話のやり取り・言いたかったこと・自分が言った文・語順コアイメージ・発音のコツ」まで出力させ、そのまま復習カード（SRS）の解説として活かす。

### 1-7. 絵カード4択の抽象的すぎるタグと選択肢の文脈重複
* **発生事象**: 絵カード4択で第3タグが「日常・誠実・前進・受容」など抽象的な感情語だった上、同じような場面（カフェ同士、時間約束同士など）が4択に並び、「どの選択肢でもあり得そう」な紛らわしい出題になっていた。
* **再発防止**:
  * 絵カードのタグは抽象的な感情ではなく「冷たいラテ」「発車寸前」「牛乳切れ」「割り勘会計」など**その英文固有の具体的な状況・モチーフ**にする。
  * ビジュアルカードには「3アイコンのイラスト図解＋シーン見出し＋4つのタグ（場所・相手・状況・焦点）」を表示して一目で場面を特定できるようにする。
  * ダミー選択肢は `selectDistinctPictureDistractors` により**意味クラスタ（Semantic Cluster）・場面カテゴリ・アイコン・全タグが4枚すべて異なるカード**のみを選出する。

### 1-8. 追加フレーズ生成で2回目以降0問になるボトルネック
* **発生事象**: 「新しいフレーズを5問追加する」を押した際、「現在追加できる新しいフレーズがありません」と出て追加できなくなった。
* **原因**:
  1. Worker プロキシの1リクエストタイムアウトが11秒と短く、かつ Step 2（監査コール）がタイムアウトすると Step 1 で生成済みの5問まで丸ごと破棄してローカルモックへ落ちていた。
  2. AI が返した JSON の軽微な揺れ（タグが9文字、ホワイトリスト外アイコン、`blocks` と `enText` の微差）を補正せずそのまま `validateAiQuestion` で捨てていた。
  3. フォールバック先の `rawMockCandidates` が固定の5問しかなく、1回追加すると2回目以降は5問とも重複判定（`duplicate_en_text`）で0問になっていた。
* **再発防止**:
  * Worker の Gemini タイムアウトを20秒に拡大し、Step 2 が失敗しても Step 1 の生成結果を活かす。
  * バリデータに通す前に `repairRawAiQuestions` でタグ長・アイコン・ブロック配列を自動整形して合格率を高める。
  * ローカル補充プールも大容量（20問以上・5問ずつ段階供給）にし、連続で追加ボタンを押しても枯渇しないようにする。

## 2. 上手くいった方針・ベストプラクティス（Keep Doing）

### 2-1. 「博士・デザイナー・コンサル」の3視点レビュー
* **良かった点**:
  * 機能やUIを直す際、**博士（認知科学・SLA）**・**デザイナー（モバイルUI・アニメーション・レイアウト工学）**・**コンサル（学習継続・心理的納得感）**の3視点で検証することで、ユーザーにとって納得感と心地よさのある実装になった（例：`TimeLimitBar` の60fpsゲージ＋緑境界マーカー、固定高さ `WordOrderBoard`）。

### 2-2. 「まず正誤、その上で色と理由」のフィードバック設計
* **良かった点**:
  * 判定色（緑・黄・赤）だけを出すと「合っていたのか間違っていたのか」「なぜ黄色なのか」が伝わらない。**「○ 正解 / × 不正解」バッジ＋1行の理由説明**を常にセットにしたことで、オンボーディングも復習も直感的に理解できるようになった。

### 2-3. 既存DBデータの自動同期・修復設計（`database.ts`）
* **良かった点**:
  * シードデータや解説を改善した際、起動時の同期処理で既存ユーザーのIndexedDB／D1データも自動更新する仕組みを入れてあるため、古いキャッシュが残ってバグが再発するのを防げた。

### 2-4. 変更後のワンストップ検証フロー
* **良かった点**:
  * 修正のたびに `npm run test && npm run lint && npm run build`（12テストファイル / 67テスト、型チェック、ESLint、Vite PWAビルド）を一気通貫で通してからコミット・プッシュ・デプロイする運用により、デグレを即座に検知できている。
