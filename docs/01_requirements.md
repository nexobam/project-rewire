# Project Rewire 要件定義書（v1.0 実装確定版）

## 1. プロジェクト概要・基本制約
* **目的**：中学英語の断片的な記憶（文字を優先する・カタカナ発音・日本語に直訳して考える・文法ルールを意識的に計算する）が残っていて、会話力はゼロの状態から、ネイティブスピードの雑談の聞き取り、英語の語順での自由発話、Miami HeatのNBAトークができる状態まで到達する。
* **利用者**：本人1名（個人利用）。アカウント機能やサーバーは作らない。
* **最終ゴール（アプリの外で測る）**：字幕なしのNBAポッドキャスト（約170wpm）を5分聴き、要点を3つ英語で言える。
* **コンテンツ比率**：**日常会話 85%（メイン軸）：Miami Heat 15%（感情のフック）**。直近100問で、Heatの割合が15%±5%（10%〜20%）に収まるように制御する。
* **ランニングコスト**：**完全0円**。ブラウザ標準の Web Speech API／Web Audio API、Gemini APIの無料枠、手動でのGemini Live連携、無料ホスティング（Cloudflare Pages または GitHub Pages）のみを使用する。
* **対象環境**：**iPhone Safari**（満員電車での片手・親指操作、ホーム画面に追加したPWA、オフライン利用）と、**PC Chrome**（大画面の2カラム表示、キーボード操作）の両方で動作するレスポンシブWebアプリ。

## 2. 学習メソッド・ビジネスルール（6大絶対ルール）

1. **翻訳思考を完全に排除する**
   * 日本語の文を英訳させる出題は全面禁止。
   * 「状況ビジュアルカード（単色SVGアイコン2つ＋日本語の場面タグ3つ）」と「音」から直接英語を出力させる。
   * 場面タグは**「場所／相手／感情」の名詞に限る**（各8文字以内）。動詞や、文の中身のヒントになる語は禁止。
2. **音が先、文字は後（Lv.1は2段階）**
   * **Lv.1前半（絵カード期）**：英文は完全に非表示。「聴く → 状況ビジュアルカード4枚から正しい場面を1枚選ぶ → 回答後のカードで初めて英文を表示」。
   * **Lv.1後半（語順ブロック期）**：文全体の字幕は非表示のまま、英単語が書かれた語順ブロックを並べさせる。英文全体は回答後に表示する。
   * **前半から後半への移行条件**：絵カードの直近30問で、正答率85%以上かつ緑が60%以上。
   * 共通：音声の再生中は選択肢を非表示にし、タイマーも止める。再生が終わった瞬間に選択肢を表示し、計測を始める。
3. **個人の速度に合わせた動的タイムリミット**
   * 選択肢が表示された瞬間を `0ms` として `performance.now()` で計測し、**反応開始時間**（最初の1タップまで）と**完了時間**を別々に記録する。
   * `perTapMs`：Lv.0診断で測ったタップ間隔の中央値（`350〜700ms`、初期値 `500ms`、設定画面から再測定可能）。
   * **語順ブロックの判定**（完了基準：`completionBudget = perTapMs × ブロック数 + 800ms`）
     * 緑（瞬発クリア）：正解、かつ反応開始 ≤ 1200ms、かつ完了 ≤ `completionBudget`
     * 黄（やや迷い）：正解、かつ反応開始 ≤ 2000ms、かつ完了 ≤ `completionBudget + 1500ms`
     * 赤（思考停止・弱点）：上記以外、またはミス
   * **絵カード・音変化4択の判定**：緑は ≤ 1500ms、黄は ≤ 3000ms、それ以外またはミスは赤。
   * **強制終了の禁止**：基準時間を過ぎても答えを自動で開かず、ユーザーが回答し終えるまで待つ（評価は赤として記録）。
   * **回答中はタイマーも残り時間も表示しない**。結果は回答後に色と秒数で表示する。
   * **轟音リプレイ救済**：選択肢表示前のリプレイは1問につき1回までペナルティなし。選択肢表示後のリプレイはタイマーをリセットするが、その問題の最高評価は黄までとする。
4. **メタ理解と体感文法**
   * 日本語の解説では直訳を全面的に禁止し、**「空間・動き・感情のコアイメージ」**と**「発音フォーム（口・舌・リズム）」**だけを提示する。
   * AIが問題を生成するときは、**パターンプラクティス**と**チャンク・ビルディング**を意図的に混ぜる。
5. **SRS（間隔反復）・インターリービング・厳密シャッフル**
   * 復習間隔の段階：`[1, 3, 7, 14, 30]` 日（緑：次の段階へ、30日段階で緑なら卒業＆90日後抜き打ち1回／黄：同じ段階のまま再スケジュール／赤：段階0に戻し卒業も取り消す）。
   * インターリービング：同じ `grammarPattern`、または同じ `sceneCategory` の問題が2問連続しないようにする。
   * 厳密シャッフル：ブロックは3〜9個。シャッフル後の表示テキスト列が `acceptableOrders` のどれとも一致しないことを保証する。重複単語はブロックIDで区別し、正誤はテキスト列で判定する。
6. **実力ベースの昇格ゲート**
   * 数値条件（①コアセット語順評価80%以上、②リスニング直近40問85%以上、③発話直近40回緑75%以上）と④ボス戦（全10問ヒントなし、黄以内8問以上）への合格によってのみ次のレベルへ進む。

## 3. 実装時に承認を得て確定した事項
1. **開発依存パッケージ（`devDependencies`）**：React 19 + TypeScript (strict) + Vite + Tailwind CSS + Vitest + ESLint 環境のビルド・テスト・カバレッジ検証・`dangerouslySetInnerHTML` 機械的禁止のため、`@vitejs/plugin-react`、`@tailwindcss/vite`、`@vitest/coverage-v8`、`@testing-library/jest-dom`、`@testing-library/user-event`、`eslint` / `typescript-eslint`、`@types/*` を追加。
2. **データモデルの補助フィールド**：要件6-1のインターフェースを完全維持した上で、`Chunk`（`promptAudioText`, `ngWords`, `soundChangeChoices`）、`ReviewState`（`wordOrderRatings`）、`AiReport`（`studyDate`, `liveLog`）、`Settings`（API呼び出し回数管理、ボス戦クールダウン、お休みチケット補充管理、Lv.4 `allEnglishMode`）、および `CoachMessage` ストアを定義。
3. **Gemini API 初期モデル**：無料枠対象の Flash 系モデルとして初期値を `gemini-2.5-flash`（設定画面で変更可能）に設定。
